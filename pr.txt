1. SUMMARY
--------------------------------------------------------------------------------
This PR adds campaign-level fund conservation property-based testing to the
aid_escrow Soroban contract test suite, verifying that per-campaign accounting
(locked + claimed + refunded <= funded) and per-campaign aggregates consistently
sum to token-level totals across randomized multi-campaign operation sequences.

It also adds a negative/deterministic bug-detection test proving the invariant
check is not vacuous: a deliberately introduced conservation bug makes the
assertion panic while the real contract state passes.

  app/onchain/contracts/aid_escrow/tests/property_based_invariants.rs
  (+528 / -16 lines)

No contract source is modified; this is test-only. The production contracts

get_campaign_token_locked, get_campaign_token_claimed), and cargo check
-p aid_escrow --tests succeeded before and after the change.

2. TESTS ADDED
--------------------------------------------------------------------------------

2.1 test_campaign_fund_conservation_invariants (property-based / randomized)
--------------------------------------------------------------------------------
Purpose: Assert campaign-level fund conservation under randomized multi-campaign
operation sequences where two campaigns share one token.

Setup:
- Seeds an escrow with one shared Stellar asset token.
- Creates camp-1 and camp-2 packages (tagged via campaign_ref metadata) plus
  untagged packages, all funded against the same token.

Operation loop (50 iterations x 30-80 randomized ops each):
- fund / create_package / claim / revoke / refund / reassign_package /
  advance_time, selected via a seeded Rng (StdRng) so runs are reproducible.
- Every operation mutates the real contract AND the caller's own per-campaign
  / untagged aggregate accounting (locked, claimed, refunded, funded).

Invariant check after EVERY operation
  (pure helper check_campaign_conservation_invariants):

  (a) Per-campaign conservation:
      For each campaign: locked + claimed + refunded <= funded
      (reads campaign_locked / campaign_claimed live from contract getters
       get_campaign_token_locked / get_campaign_token_claimed).

  (b) Cross-campaign consistency against token-level totals:
      sum(campaign_locked) <= token_locked   (allowing untagged remainder)
      sum(campaign_claimed) <= token_claimed
      sum(campaign_funded) <= token_funded
      untagged_* never attributed to any campaign.

Result: 2 passed, 0 failed (both new tests) in ~79s.

2.2 test_campaign_conservation_bug_detection (deterministic negative test)
--------------------------------------------------------------------------------
Purpose: Prove the invariant check catches real conservation violations instead
of being a vacuous assertion.

Flow:
1. Constructs a known-good multi-package state across camp-1, camp-2, and one
   untagged package (claim, disburse, revoke, refund-after-expiry).
2. Calls check_campaign_conservation_invariants against the real contract state
   -> must pass.
3. Deliberately injects a conservation bug: undercounts camp-1's funded
   accounting by one package's amount (simulating a skipped increment_locked
   campaign delta).
4. Re-runs the same check against corrupted values via catch_unwind -> must
   panic.
5. Asserts the panic occurred (acceptance criterion #3 from issue #1407).
